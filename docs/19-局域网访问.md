## 19.6 机制说明（为什么这样改）

### 19.6.1 监听

- 后端：`HOST`（Nest 监听）默认 `0.0.0.0`；E2E 编排新增 `API_HOST` 默认 `0.0.0.0`。
- 前端：Next CLI `-H 0.0.0.0`，否则 `next start` 默认只监听 localhost。
- S3 替身：`E2E_S3_HOST=0.0.0.0`（由 `run-backend` 在 LAN 模式下自动传入）。

### 19.6.2 CORS 策略（REST 与 WS 共用一份）

`server/src/config/cors.ts` 把 `CORS_ORIGINS` 解析为：

```ts
{ exact: string[], patterns: RegExp[], lanOrigins: string[], allowed(origin): boolean }
```

支持三种条目：

| 写法 | 含义 |
| --- | --- |
| `http://localhost:3100` | 精确 origin |
| `http://192.168.1.*:3100`、`http://192.168.*:*`、`http://10.*:3000` | 私网通配（编译为正则） |
| `http://*.local:3100` | mDNS 主机名通配 |

安全约束（编译期直接抛错）：

- 禁止裸 `*`（`*`、`http://*:3100` 都会被拒绝）；
- 通配网段必须是 `10.*` / `192.168.*` / `172.16-31.*`，`192.*.1.*` 这类会匹配公网的写法被拒绝；
- 端口通配只允许 localhost 或私网 IP。

`LAN_ORIGINS_AUTO=true` 时，若显式列表里没有任何私网 origin，服务端会探测本机私网 IPv4 并追加 `http://<ip>:3100`、`http://<ip>:3000`。

- **REST**：`main.ts` 把 `cors.origin` 设为函数，命中策略才回 `Access-Control-Allow-Origin`。
- **WS**：Socket.IO 的 `cors.origin` 只影响响应头，不会拒绝握手；因此 `io-adapter.ts` 额外设置 `allowRequest`，在 Upgrade 阶段对非法 Origin 直接返回 `400 CORS_ORIGIN_NOT_ALLOWED`。没有 Origin 的 Node 客户端/服务端调用放行。

### 19.6.3 S3 预签名与直传

- 预签名用**公网 client**（`S3_PUBLIC_ENDPOINT`），数据面（HEAD/GET/DELETE）用**内网 client**（`S3_ENDPOINT`），见 `docs/12 §12.7`。
- **Phase1 起自动推导**：`run-backend.mjs` 的 `s3Config.publicEndpoint` 规则为
  1. 显式 `S3_PUBLIC_ENDPOINT` 最优先；
  2. 否则若 `API_HOST=0.0.0.0` 且有 LAN IP → `http://<LAN_IPS[0]>:<S3_ENDPOINT 的端口>`（默认 `http://192.168.1.9:9000`）；
  3. 否则回退 `S3_ENDPOINT`（`http://127.0.0.1:9000`）。
  `run.json` 的 `s3.publicEndpoint` / `lan.s3PublicEndpoint` 记录实际生效值。
- **前置条件**：rclone/MinIO 必须监听 `0.0.0.0`（例如 `rclone serve s3 ... --addr 0.0.0.0:9000`）；若仍绑 `127.0.0.1`，手机会拿到 `http://<LAN_IP>:9000` 但连接被拒。
- 生产 MinIO：用独立端口或独立子域作为 `S3_PUBLIC_ENDPOINT`，不要走 `/files/*` 前缀反代（SigV4 会签 path）。

### 19.6.4 前端地址注入

```ts
// web/src/lib/api.ts
NEXT_PUBLIC_API_BASE 有值 → 用它（构建期内联，改了要重新 build）
否则 → http://<window.location.hostname>:3000   （localhost 仍 localhost）
```

WS 客户端 `io(`${API_BASE}/ws`, { path: '/socket.io' })`，因此地址推导同时覆盖 REST 与 WS。

### 19.6.5 登录会话结论（Bearer + localStorage，无 Cookie）

- 前端 `web/src/lib/session.ts` 把 access/refresh token 存在 **localStorage**，请求头 `Authorization: Bearer`；未使用任何 Cookie。
- 因此跨设备访问**不涉及** Cookie 的 `SameSite` / `Domain` / `Secure` 配置，后端也无需 CSRF token。
- HTTP（非 localhost）属于**非 Secure 上下文**：`localStorage` 可用；Web Push、`crypto.subtle`（Web Crypto）、`getUserMedia`、Service Worker 等可能不可用。本系统未使用这些能力（推送默认关闭），故手机通过 `http://192.168.1.9:3100` 使用不受影响。
- token 仍是 15 分钟 access + 30 天 refresh，与局域网无关；公共 WiFi 场景注意不要把 URL/token 分享出去。

## 19.10 排障清单

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 手机打不开 `:3100` | 防火墙未放行 / 前端仍监听 127.0.0.1 | 管理员 PowerShell 加规则（见下）；确认 `next start -H 0.0.0.0` |
| 页面能开但登录报 `NETWORK` | 前端推导的 API 地址不可达 / 后端未监听 0.0.0.0 | 手机浏览器看请求 URL 是否 `http://<LAN>:3000`；`curl http://<LAN>:3000/healthz` |
| 登录 403/CORS 报错 | `CORS_ORIGINS` 缺少 `http://<LAN>:3100` | 加白名单或保持 `LAN_ORIGINS_AUTO=true`（需无显式私网项）；**改 env 后必须重启进程** |
| WS 一直重连 | 反代/直连路径写错 | 传输路径是 `/socket.io/`，命名空间 `/ws`；浏览器 DevTools 看 `ws://<LAN>:3000/socket.io/?EIO=4&transport=websocket` |
| WS 报 `websocket error` | Origin 不在白名单（`allowRequest` 拒绝） | 把页面来源加进 `CORS_ORIGINS`；对照服务端日志 |
| 上传失败 403（S3） | 手机直传地址不是 `S3_PUBLIC_ENDPOINT` / MinIO 未配 CORS | 检查 presign 返回的 `uploadUrl` host；E2E 替身已内置 CORS 代理；生产 MinIO 需配 CORS |
| 上传 404/SignatureDoesNotMatch | `S3_PUBLIC_ENDPOINT` 带了路径前缀，或反代改写了 Host | 用独立端口/子域；不要用 `/files/*` 反代 |
| IP 变了访问不了 | DHCP 换 IP | 重跑 `ops/lan.ps1`；或 `ipconfig /release && ipconfig /renew`；路由器里给 MAC 绑定固定 IP |
| 改了 env 不生效 | 进程读的是启动时 snapshot | 重启 `run-backend` 与前端 dev/start 进程；永久变量需新开终端 |
| 局域网能 ping 通但页面打不开 | 公司/公共 WiFi 开启 AP 隔离 / 客户端隔离 | 换家用路由器或关闭隔离；也可用手机热点反向让电脑接入 |
| `:9100` 被占用 | 上一次 s3-server 未退出 | `node ops/e2e/s3-server.mjs --stop`，或改 `E2E_S3_PORT` |
| 手机能登录、能看历史，但发消息完全没反应 | **HTTP 非安全上下文没有 `crypto.randomUUID`**（只存在于 HTTPS/localhost）；前端发送/上传在调用处抛异常，请求根本没发出 | 已用 `web/src/lib/uuid.ts` 的 `getRandomValues` 兜底替换；若自行改前端，注意不要再直接调用 `crypto.randomUUID()` |
| 手机时间不对导致登录异常 | 系统时间偏差 | 手机开启自动时间（JWT 依赖时间） |

```powershell

New-NetFirewallRule -DisplayName 'Dijiang S3  9100' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 9100
```

## 19.11 安全边界

- 本方案面向**可信局域网**：没有 HTTPS、没有 WAF；不要把 3000/3100/9100 映射到公网。
- CORS 只是浏览器同源策略的放宽，**不是认证**；真正的访问控制仍是 Bearer token + 服务端权限矩阵。
- access token 15 分钟、refresh 30 天；公共网络下不要把链接连同 localStorage 里的 token 交给他人设备。
- `S3_PUBLIC_ENDPOINT` 是直传入口，建议生产使用独立子域 + HTTPS + MinIO 桶级 CORS 白名单。
- 若必须 HTTPS：用 Caddy/nginx 终止 TLS，把 `S3_PUBLIC_ENDPOINT` 与 `CORS_ORIGINS` 都改成 `https://`，并保证 WS 走 `wss://`（传输路径不变）。

## 19.13 本机现状补充（明早验收前先看这一段）

1. **防火墙**：本机三张配置文件（Domain/Private/Public）当前都是 **Disabled**，所以不需要加规则就能从局域网访问；**如果以后打开了防火墙，必须放行入站 3000/3100/9100**（见 §19.10 的命令），否则手机只会“一直转圈”。

```powershell
Get-NetFirewallProfile | Select-Object Name, Enabled
```

2. **启动前先确认三件事**（用管理员以外的普通终端即可）：

```powershell
Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.IPAddress -like '192.168.*' -or $_.IPAddress -like '10.*' } | Select-Object InterfaceAlias, IPAddress
node ops/e2e/run-backend.mjs --status      # 若脚本没有 --status，看 reports/e2e/run.json 的 lan 段
curl.exe -s http://<LAN_IP>:3000/readyz    # 期望 {"status":"ok",...}
```

3. **IP 变了怎么办**（DHCP 最常见）：
   - 看 `reports/e2e/run.json` → `lan.ips`，这是后端启动时探测到的 IP；
   - 手机端刷新页面即可（前端按 `location.hostname` 推导 API 地址，不需要重新 build）；
   - 若后端是在 IP 变化**之前**启动的，CORS 里的旧 IP 已失效：重启 `run-backend`（会自动重新探测），或临时设 `CORS_ORIGINS=http://<新IP>:3100,http://<新IP>:3000`；
   - 想一劳永逸：路由器里给本机 MAC 绑定固定 IP，或改用手动 IP。

4. **一次完整重启顺序**（后端改了 env 必须重启进程）：

```powershell
node ops/e2e/run-backend.mjs --stop
node ops/s3-server.mjs --stop          # 若单独起过 S3 替身（可选，run-backend --with-s3 会自己拉）
# 后端（自动探测 LAN IP、自动 CORS、S3 公网端点指向 LAN IP）
node ops/e2e/run-backend.mjs --with-s3 --skip-build
# 前端（新终端）
cd web
pnpm start -H 0.0.0.0 -p 3100          # 或 pnpm dev
```
