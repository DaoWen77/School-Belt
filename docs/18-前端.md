## 1. 范围

本次交付的是可运行的真实前端，不是静态设计稿：

### 3.1 响应信封（真实后端）

`server/src/common/interceptors/transform.interceptor.ts` 把所有成功响应包成：

```json
{ "ok": true, "data": { ... }, "requestId": "..." }
```

异常过滤器 `all-exceptions.filter.ts` 包成：

```json
{ "ok": false, "error": { "code": "AUTH_INVALID", "message": "..." }, "requestId": "...", "timestamp": "..." }
```

`lib/api.ts` 因此做两件事：

- `api()` 成功分支：`body.ok === true && 'data' in body` 时返回 `body.data`（`@RawResponse()` 的 /healthz 之类原样返回）；错误分支从 `body.error.code` / `body.error.message` 读真实码，`requestId` 一并保留；Throttler 的 429 不经过业务错误信封，兜底映射为 `RATE_LIMITED`。
- `doRefresh()`：`const data = json?.data ?? json`，再读 `accessToken` / `refreshToken`。

这条链路已用真实登录验证：`POST /auth/login` → `data.accessToken` → `GET /me`、`/channels`、`/conversations` 全部解包成功。

## 4. 页面与交互

### 4.1 `/login`

- 两种模式：`登录`（POST `/auth/login`）与 `邀请码注册`（POST `/auth/register`，含 displayName + inviteCode）。
- 成功后写 access/refresh（内存 + localStorage）并 `router.replace('/')`。
- 失败显示服务端真实 `code`（`AUTH_INVALID` / `INVITE_INVALID` / `RATE_LIMITED`…）；网络不可达显示 `NETWORK` + 「无法连接 API」。
- 页脚/字段区始终打印真实 `NEXT_PUBLIC_API_BASE` 与 WS 路径，方便判断连的是哪套服务；不写死任何账号密码，输入框只给 `chen` / `至少 8 位` 这类占位提示。

### 4.2 `/` 主界面

三栏结构完全复用甲套 `dj-shell` / `dj-rail` / `dj-main` / `dj-chat-wrap` / `dj-side`：

- **左栏**：
  - `频道`：GET `/channels`，显示 slug、公开/私密、未读数。
  - `私聊`：GET `/conversations` 中 `kind=dm`，DM 标题显示对方显示名（`peer`，否则按成员列表排除自己）；「新建私聊」从 GET `/conversations/users` 选人 → POST `/conversations/dm`。
  - `群聊`：`kind=group`，标题为群名、人数；「新建群聊」填名称 + 多选成员 → POST `/conversations/group`。
- **中栏**：
  - 头部：会话名、类型、可见性、成员数、未读、最后一条时间。
  - 消息流：GET `/channels/:id/messages?limit=50`，`加载更早的信号` 用 `direction=older` + `cursor`。
  - 线程：有回复的消息显示「展开 n 条回复」，展开时 GET `/messages/:rootId/thread`；线程内可回复（`message:send` 带 `parentId`）。
  - 输入框：Enter 发送、Shift+Enter 换行、IME 组字期间不发送；单条上限 8000 字。
  - 发送失败的消息显示真实 `code` 与「重发」；重发复用同一个 `clientMsgId`。
- **右栏**：会话信息（类型/可见性/对方/成员/我的角色/未读/最后活动）、成员列表（角色 + 移除）、群聊管理（改名 / 加人 / 退出群聊，仅 moderator 显示改名与加人）。

### 4.3 `/settings`

账号（GET `/me`）、链路（API/WS/path/凭证存储）、已知限制、退出登录。所有数值来自真实接口，接口挂了显示错误码。

### 4.4 私聊 / 群聊动作清单（契约 §B）

| 动作 | 接口 | 入口 |
| --- | --- | --- |
| 私聊列表 | GET `/conversations`（`kind=dm`） | 左栏「私聊」 |
| 新建私聊 | GET `/conversations/users` + POST `/conversations/dm` | 左栏「新建私聊」→ 选人 |
| 私聊互发 | `message:send` / GET `/channels/:id/messages`（DM 的 id 当 channelId） | 中栏输入框 / 消息流 |
| 群聊列表 | GET `/conversations`（`kind=group`） | 左栏「群聊」 |
| 新建群聊 | POST `/conversations/group`（名称 + 多选成员） | 左栏「新建群聊」 |
| 群内发消息 | `message:send` | 中栏输入框 |
| 改名 | PATCH `/conversations/:id`（moderator） | 右栏「群聊管理」 |
| 加人 | POST `/conversations/:id/members`（moderator） | 右栏「群聊管理」 |
| 移除 | DELETE `/conversations/:id/members/:userId`（moderator） | 成员行的「移除」 |
| 退出 | DELETE `/conversations/:id/members/:meId`（本人） | 右栏「退出群聊」 |
| 实时 | `conversation:created/updated/removed` | 收到后重取 `/conversations`，被移除时清空当前选择 |

## 5. 状态管理

单页状态集中在 `Workspace.tsx`，没有引入 Redux/Zustand：

| 状态 | 内容 | 来源 |
| --- | --- | --- |
| `me` | 当前用户 | GET `/me` |
| `channels` | 社区频道列表 + 未读 | GET `/channels`、`ready.channels`、`message:new` |
| `conversations` | DM + 群聊列表 | GET `/conversations`、`conversation:*` 事件后重取 |
| `users` | 可发起会话的用户 | GET `/conversations/users` |
| `selection` | 当前会话 `{id, kind}` | 用户点击 / 创建成功后 |
| `messages` | 当前会话消息（含本地 pending） | 历史分页 + `message:new` + ack |
| `threads` | 每个 root 的展开/加载/回复 | 点击展开时 GET 线程 + WS |
| `members` | 当前会话成员 | GET `/channels/:id/members` |
| `conn` | Socket 状态机 | Realtime 回调 |
| `fatal` | 「链路未连接」致命态 | 首次装载失败（NETWORK/HTTP 错误） |
| `actionError` | 操作级错误（真实 code） | 发送/群聊操作/线程加载失败 |

关键约定：

- 消息去重按 `id`；乐观消息 `id = local:<clientMsgId>`，服务端消息按 `clientMsgId` 替换本地 pending。
- 主消息流不渲染 `threadRootId != null` 的回复；回复进入对应线程。
- 已读：进入会话、收到新消息时把 seq 写入 `pendingReadRef`，**500ms 节流**后 POST `/channels/:id/read`，只上报当前会话。
- 401：`api()` 里 single-flight refresh 一次后重放；refresh 失败清空凭证并回 `/login`。
- WS 进入 `auth-error`（`AUTH_INVALID` / `FORBIDDEN` / refresh 失败）时同样清凭证并回 `/login`，不在失效链路上重试。

## 6. WS 时序

### 6.1 连接

```ts
io(`${NEXT_PUBLIC_API_BASE}/ws`, {
  path: NEXT_PUBLIC_WS_PATH,        // /socket.io
  auth: { token: accessToken },
  transports: ['websocket'],
  reconnection: false,              // 退避由前端自己控制，便于处理 TOKEN_EXPIRED
});
```

- 连接成功 → 服务端下发 `ready`；前端按 `ready.channels` 校准未读/最后已读。
- `ready` 后对当前会话 `channel:join`，并用本地 `lastSeq`（消息 id 的十进制字符串）调 `GET /channels/:id/messages?direction=newer&cursor=<base64url(seq:id)>` 循环补拉，直到 `hasMore=false`；补拉结果按 id 去重。
- `connect_error`：
  - `TOKEN_EXPIRED` → REST refresh 一次 → 用新 access 重连；
  - `AUTH_REQUIRED` / `AUTH_INVALID` / `FORBIDDEN` → 停在「登录状态失效」，不再重试；
  - 其它（含网络）→ 指数退避 **1/2/4/8/16s** 重连。
- `disconnect`（非主动）→ 同一退避序列；重连成功后重新 join + 补拉。

### 6.2 发送（幂等）

```text
输入 → crypto.randomUUID() 生成 clientMsgId
     → 插入 local:<clientMsgId>（pending 态，半透明）
     → socket.timeout(5000).emit('message:send', { channelId, clientMsgId, kind:'text', body, parentId? })
     → ack { ok:true, message }：按 clientMsgId 移除 pending，按 id 去重后落位
     → ack { ok:false, code }：标记失败，显示真实 code + 「重发」
     → 5s 无 ack：同一 clientMsgId 重发，最多 3 次（1s/2s/4s 退避）
```

服务端 `(channel_id, sender_id, client_msg_id)` 唯一键保证最多一条；`message:new` 与 ack 谁先到都按 id/clientMsgId 去重。

### 6.3 会话事件

| 事件 | 前端动作 |
| --- | --- |
| `message:new` | 当前会话：合并 + 上报已读；其它会话：未读 +1 |
| `message:updated` / `message:deleted` | 当前会话内按 id 替换 / 标记删除 |
| `conversation:created` / `conversation:updated` | 重新 GET `/conversations` |
| `conversation:removed` | 从列表移除；若为当前会话则清空选择 |

线程回复（`threadRootId`）只进对应线程；线程未展开时只更新 root 的回复计数。

## 8. 已知限制 / 未实现项

1. **附件上传未做入口**：契约与 API 已就绪（`POST /files/presign` 等），本次前端只读展示消息里的附件名，未做选择文件/直传/进度。
2. **卡片只读**：消息中的 `cardId` 只显示编号；投票/任务/灵感/作品四类卡片页面不在本次范围。
3. **搜索、通知中心、已读回执 UI 未做**：`docs/_contract-v1.2.md` §G 也把这些列为非目标（已读只上报，不展示「对方已读」）。
4. **消息编辑/删除入口未做**：接口已有，前端不做入口（契约 §G）。
5. **线程没有独立房间订阅**：线程回复通过频道房的 `message:new` 实时合并；未调用 `thread:join`（频道房已能收到回复，契约 §13.3.1 说明回复同时进频道房与线程房）。
6. **私聊/群聊依赖后端 v1.2 模块**：已与真实后端联调（`/conversations`、`conversation:*`）；若后端未部署该模块，对应分组为空、创建操作显示真实错误码，不会造数据。
7. **未做输入中提示**：契约只定义 C→S `typing`，没有 S→C 广播（docs/13 §13.8），前端未发 `typing`。
8. **多端已读合并**只按服务端 `receipt:update` 忽略处理（未消费），因为契约不要求已读回执 UI。
9. **自动化 UI 测试不在本任务范围**：`ops/e2e/` 的 Playwright 冒烟（登录→频道发消息→新建 DM→发消息→建群→发消息）负责端到端；本任务只交付 `next build` + Chrome CDP 截图脚本（`reports/frontend/capture.cjs`、`capture-live.cjs`）。

### 10.2 附件上传链路

```text
选择/拖拽/粘贴文件
 → 客户端预检：类型白名单 + 大小（图片 20MB / 音频 50MB / 文档 100MB / 压缩包 100MB / 视频 200MB）
 → POST /files/presign { channelId, filename, mime, size } → { fileId, uploadUrl, method:'PUT', headers, expiresIn }
 → XHR PUT uploadUrl（带 headers，监听 upload.onprogress 显示百分比）
 → POST /files/:id/complete {}
 → 发消息：message:send attachmentIds:[fileId]（或 POST /cards kind=material fileIds）
```

- 签名读地址：`GET /files/:id/url?variant=original|preview` → `{ url, expiresIn }`；`lib/fileUrl.ts` 按 `fileId:variant` 缓存并在过期前 60s 重新签名，进入会话时 `warmFileUrls()` 批量预热。
- 图片：缩略用 `preview`（无预览对象时服务端回退 original），大图用 `original`；文件卡：`original` + `download`。
- 上传失败保留服务端真实 code（`FILE_TOO_LARGE` / `FILE_TYPE_NOT_ALLOWED` / `FILE_NOT_READY` / `NETWORK` / `HTTP_xxx`），UI 红色细线行 + 文案，不伪造成功。

### 10.3 素材库

- `GET /channels/:id/cards?kind=material&limit=50`；筛选按附件 mime 归为 图片/文档/音频/其他。
- 上传完成后自动 `POST /cards { channelId, kind:'material', title, fileIds }`；服务端同时广播 `message:new(kind=card)` + `card:created`，聊天流出现紧凑卡、素材视图自动刷新。
- 空态、加载骨架、失败通知（真实 code + 重试）。

### 10.4 投票

- 列表：`GET /channels/:id/cards?kind=vote`，每张卡再取 `GET /cards/:id/results`（`counts/total/voters/closed/multi/anonymous/closesAt`）。
- 新建：`POST /cards { channelId, kind:'vote', title, options:[≥2], data:{ multi, anonymous, closesAt } }`。
- 投票：`POST /cards/:id/vote { optionIds }`；多选只允许选中多个，单选限 1；截止后按钮禁用；提交后票数条与实名投票人列表刷新。
- 匿名投票 `voters=[]`，前端不渲染投票人。

### 10.5 任务

- 列表：`GET /channels/:id/cards?kind=task`；按 `taskStatus`（todo/doing/done）分三列，`dueAt` 显示截止日，`assigneeIds` 用成员名映射显示「指派：陈工、林测绘」。
- 新建：`POST /cards { channelId, kind:'task', title, assigneeIds, dueAt }`。
- 状态流转：`PATCH /cards/:id { taskStatus }`；只有作者 / moderator / owner / admin 显示控件（服务端仍会校验）。正常 Chrome 已验证 `进行中 → 已完成`。

### 10.6 消息编辑 / 删除

- 仅自己的、非 pending/failed 的消息显示「编辑」「删除」。
- 编辑：`PATCH /messages/:id { body }`（纯文本），成功后 `editedAt` 显示「已编辑」；`message:updated` 同步其它端。
- 删除：先内联确认，再 `DELETE /messages/:id`（软删），本地与 `message:deleted` 都显示「该信号已被删除。」。

### 10.7 卡片消息

- `message.kind === 'card' && cardId` 时按 cardId 拉 `GET /cards/:id` 渲染紧凑卡：类型/标题/选项数/任务状态/截止/附件缩略。
- 「在素材/投票/任务视图查看」直接切到对应视图。
- 建卡后服务端广播 `card:created`（视图刷新）与 `message:new`（聊天流插入），前端不再手工造消息。

### 10.8 联调坑（必读）

1. **REST CORS 默认只放行 GET/HEAD/POST**：`server/src/main.ts` 的 `app.enableCors` 未显式 `methods` 时，浏览器对 `PATCH/DELETE` 的预检拿不到方法 → 前端显示 `NETWORK: Failed to fetch`（不是前端 bug）。修复后：
   `OPTIONS /api/v1/messages/1`（Origin `http://localhost:3100`, Request-Method `PATCH`）→ `204`，`Access-Control-Allow-Methods: GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS`。
   受影响功能：消息编辑/删除、任务状态、群聊改名、移除/退出成员。
2. **S3/MinIO 桶 CORS**：浏览器直传 `PUT` 到对象存储前会预检；桶必须允许来源 `http://localhost:3100`、方法 `PUT/GET`、请求头 `content-type`。本机 e2e 用 **rclone S3（9000，`--allow-origin *`）** 验证；生产 MinIO 也必须配桶 CORS。
3. **地址统一用 `http://localhost:3100`**：CORS 白名单按字符串匹配，`127.0.0.1:3100` 会被拒。
