# 16 · 本地启动

> 目标：任意开发机（Windows / macOS / Linux）30 分钟内起一套完整环境。
> 交付约束：本次交付**未启动长期服务**，本机也无 Docker/PG/Redis/MinIO，因此“运行时”部分按已验证的构建与单测给出，未跑通的地方在 §16.8 明确标注。

## 16.2 路径 A：docker compose 一键启动（推荐）

```bash
cd ops
cp .env.example .env          # 首次：建议改 JWT 密钥与密码
docker compose up -d --build  # postgres/redis/minio/minio-init/api/caddy
```

Linux/macOS/WSL 也可用 Makefile（会自动生成 `.env`）：

```bash
make -C ops up          # 构建 + 启动
make -C ops ps          # 查看状态
make -C ops logs-api    # 跟踪 API 日志
make -C ops down        # 停止（保留数据卷）
```

Windows PowerShell：

```powershell
cd ops
.\start.ps1             # 启动 + 等待 PG 健康 + 迁移 + owner 初始化 + 种子
.\start.ps1 -Logs       # 跟踪日志
.\start.ps1 -Down       # 停止
```

启动后的地址：

| 入口 | 地址 |
| --- | --- |
| 健康检查（不走前缀） | http://localhost:3000/healthz 、/readyz |
| REST API | http://localhost:3000/api/v1 |
| WebSocket | 传输路径 `ws://localhost:3000/socket.io/`，命名空间 `/ws`；Caddy 后为 `wss://域名/socket.io/` |
| Caddy 统一入口 | http://localhost/api/v1 |
| MinIO 控制台 | http://localhost:9001（`minioadmin / minioadmin`） |
| 对象直传（浏览器） | `S3_PUBLIC_ENDPOINT`，默认 `http://localhost:9000`（**必须是浏览器可达地址，且不能带路径前缀**） |

`minio-init` 容器会在 MinIO 健康后自动创建 `S3_BUCKET`（默认 `dijiang`）。

> **预签名 URL 与反向代理**：SigV4 会签名完整 path（含 bucket，如 `/dijiang/channels/...`）。
> 因此对象存储**不能**走 Caddy `/files/*` 这类前缀反代（即便 `handle_path` 去前缀，MinIO 看到的 path 与签名 path 不一致 → `SignatureDoesNotMatch`）。
> 正确做法：`S3_PUBLIC_ENDPOINT` 指向「MinIO 独立端口」（compose 已映射 9000）或「独立子域」（该子域直接指向 `minio:9000`）。
> Caddy 只反代 `/api/*` 与 `/socket.io/*`，不再代理对象存储。

## 16.3 数据库迁移

镜像里自带 Prisma CLI（`prisma` 在 `dependencies` 中），可直接在容器里跑：

```bash
make -C ops migrate
# 等价于：
docker compose -f ops/docker-compose.yml run --rm --no-deps api \
  node node_modules/prisma/build/index.js migrate deploy
```

迁移文件只有一个是手写 SQL：`server/prisma/migrations/0001_init/migration.sql`（扩展 → 枚举 → 18 表 → 循环 FK → 索引）。`migrate deploy` 会把它记入 `_prisma_migrations` 并执行。

本机直跑（PG 已在 localhost:5432 时）：

```bash
cd server
pnpm install
pnpm prisma:generate
cp .env.example .env
pnpm db:migrate
```

## 16.4 首次引导（owner 初始化）

系统没有“注册即 owner”的入口：第一个 owner 必须由脚本创建，之后所有用户通过邀请码注册（契约 §5）。

```bash
# 容器内
make -C ops init-owner      # 读取 ops/.env 的 OWNER_HANDLE / OWNER_PASSWORD / OWNER_DISPLAY_NAME

# 本机直跑
cd server
node --env-file=.env dist/scripts/init-owner.js
```

脚本行为（幂等）：

1. 若已存在 `global_role='owner'` 的用户 → 跳过创建；
2. 否则用 `OWNER_PASSWORD`（≥8 位，argon2id）创建 owner，并建立默认 `user_settings`；
3. 确保三个验收频道存在：`#全域播报(general)`、`#素材工坊(archive)`、`#第三协议(protocol，私密)`，并把 owner 设为频道 moderator。

> 之后创建普通账号：owner/admin 调用 `POST /api/v1/invites` 拿明文邀请码（仅返回一次）→ 受邀者 `POST /api/v1/auth/register`。

## 16.6 本机直跑（不装 Docker）

前提：本机已有 PostgreSQL 16 / Redis 7 / MinIO（或任何 S3 兼容存储）。

```bash
cd server
pnpm install
cp .env.example .env          # 填 DATABASE_URL / REDIS_URL / S3_*
pnpm prisma:generate
pnpm db:migrate
pnpm build
node --env-file=.env dist/scripts/init-owner.js
node --env-file=.env dist/scripts/seed.js
pnpm start                    # node dist/main.js
```

开发态只跑构建与单测（不需要任何外部服务）：

```bash
cd server
pnpm install
pnpm build      # tsc -p tsconfig.build.json
pnpm test       # vitest run（8 个文件 63 例，纯内存 fake，不连库）
```

压测脚本（需本机安装 k6，且服务已启动）：

```bash
k6 run -e WS_URL=ws://localhost:3000/socket.io/ \
  -e ACCESS_TOKEN=<accessToken> -e CHANNEL_ID=<频道 uuid> \
  -e VUS=50 -e DURATION=2m ops/loadtest/k6-chat.js
```

阈值（docs/09 §1 S2 / §10）：50 VU 持续 2 分钟，发送 ack P95 < 150ms、P99 < 300ms、失败率 < 1%。
脚本按 Engine.IO v4 + Socket.IO v4 帧格式手工收发，namespace 为 `/ws`、传输路径为 `/socket.io/`（见 docs/13 §13.1）。

## 16.7 冒烟验证

```bash
# 1) 探针
curl -fsS http://localhost:3000/healthz
curl -fsS http://localhost:3000/readyz

# 2) 登录（seed 后）
curl -fsS -X POST http://localhost:3000/api/v1/auth/login \
  -H 'content-type: application/json' \
  -d '{"handle":"founder","password":"Dijiang#2026"}'

# 3) 带 token 拉频道（把 <TOKEN> 换成上一步的 accessToken）
curl -fsS http://localhost:3000/api/v1/channels \
  -H "authorization: Bearer <TOKEN>"

# 4) 发消息（REST 兜底通道，与 WS 同语义）
curl -fsS -X POST http://localhost:3000/api/v1/channels/<CHANNEL_ID>/messages \
  -H "authorization: Bearer <TOKEN>" -H 'content-type: application/json' \
  -d '{"clientMsgId":"11111111-1111-4111-8111-111111111111","kind":"text","body":"调度记录：连通性验证"}'

# 5) 邀请
curl -fsS -X POST http://localhost:3000/api/v1/invites \
  -H "authorization: Bearer <TOKEN>" -H 'content-type: application/json' \
  -d '{"maxUses":1,"expiresInDays":7,"note":"验收"}'
```

预期：`/healthz` 返回 `{"status":"ok",...}`；`/readyz` 三项检查（postgres/redis/s3）全绿；重复第 4 步同一 `clientMsgId` 返回 `dup:true` 且不新增消息。

## 16.8 常见故障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `prisma generate` 失败，提示引擎下载 | 网络无法访问 Prisma 二进制源 | 保持代理/镜像；本仓库 schema 已在交付机验证可生成。若长期不可用，按 `docs/12 §12.1` 切 Drizzle/pg |
| 启动报 `环境变量校验失败: DATABASE_URL` | 未放 `.env` 或变量名拼错 | `node --env-file=.env`；compose 用 `env_file` |
| `/readyz` 返回 503，`s3:false` | MinIO 未起 / bucket 不存在 / 密钥错 | `docker compose ps`；确认 `minio-init` 成功；`S3_FORCE_PATH_STYLE=true` |
| `/readyz` 返回 503，`postgres:false` | PG 未健康或连接串错 | `pg_isready`；核对 `DATABASE_URL`；容器内 host 是 `postgres` 不是 `localhost` |
| `/readyz` 中 `redis` 标记“内存降级” | 未配置 `REDIS_URL` | 单实例可接受；多实例广播必须配 Redis |
| WS 连不上 / 400 | 用了 polling 或反代未透传 Upgrade | 客户端 `transports:['websocket']`；反代路径必须是 `/socket.io/*`（不是 `/ws`）；Caddy 已默认透传 Upgrade；Nginx 需 `proxy_set_header Upgrade` |
| WS `connect_error: AUTH_INVALID` | token 未带/已过期/不是 access | 重新登录；过期先 REST `/auth/refresh` |
| WS 连 `/rtc` 报 `NOT_IMPLEMENTED` | 契约 §11 预留能力，开关关闭/开启都拒绝 | 预期行为，客户端不应重试 |
| 通知未推送（`push_status=skipped`） | `PUSH_ENABLED=false` / 未配 VAPID 或 FCM / 用户在线 / DND / 级别为 none | 按 docs/07 与 `push-decision.ts` 规则排查 |
| 登录 429 `RATE_LIMITED` | 契约 §9：5 次/分钟/IP + 10 次/小时/账号 | 等窗口结束；`retryAfterMs` 在错误体里 |
| 发消息 403 `NOT_CHANNEL_MEMBER` | 非频道成员（公开频道也要求入群，owner/admin 例外） | 先由 moderator 调用 `POST /channels/:id/members` |
| 发消息 403 `MUTED` | 频道或全站禁言未到期 | 错误体带 `until` |
| 上传 complete 报 `FILE_NOT_READY` | PUT 未完成/大小不符/对象不存在 | 检查 MinIO 控制台对象；确认 `Content-Type` 与签名一致 |
| 上传 complete 报 `FILE_TYPE_NOT_ALLOWED` | 魔数与声明 MIME 不一致 | 用真实文件测试；白名单见 `common/utils/mime.ts` |
| 中文搜不到消息 | `simple` 分词不切中文 | 已内置 `pg_trgm` ILIKE 兜底；确认 `pg_trgm` 扩展已创建 |
| 前端跨域失败 | `CORS_ORIGINS` 未包含来源 | 逗号分隔追加；带 credentials 时不能用 `*` |
| pnpm 提示 `ERR_PNPM_IGNORED_BUILDS` | pnpm 12 默认阻止构建脚本 | `server/pnpm-workspace.yaml` 已列 `allowBuilds`；若仍报错执行 `pnpm approve-builds --all` |
| 端口被占用 | 3000/5432/6379/9000 冲突 | 改 `ops/.env` 的 `API_PORT/POSTGRES_PORT/REDIS_PORT/MINIO_PORT` |
